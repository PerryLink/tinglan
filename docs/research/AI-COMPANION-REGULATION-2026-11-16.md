# AI 拟人化互动服务监管研究：汀岚/Famling 合规-by-design（2026-11-16）

> 状态：研究稿 · **非法律意见** · 不构成对任何具体产品的合规结论或免责依据。法规以官方原文为准；正式发布/运营前须由执业律师出具意见，并与属地省级网信部门沟通。
> 范围：桌宠汀岚（工作助手定位 + 可选 roleplay/情感陪伴）、TTS、记忆、DeepSeek 网页对话导入、Advisers 形象；面向中国用户、可能公开 GitHub/分发。
> 复核：2026-11-16。法条引用以 2026-04-10 公布稿（32 条、四章）为准，不采用二手解读中的条数/罚则转述。

## 0. 结论速览

1. **法规真实身份**：《人工智能拟人化互动服务管理暂行办法》，国家网信办、国家发改委、工信部、公安部、市场监管总局**五部门联合部门规章**（网信办令第 21 号）。2026-02-02 审议通过，**2026-04-10 公布，2026-07-15 施行**；截至 2026-11-16 **现行有效**，未检索到修订/废止公告。2025-12-27 的《征求意见稿》是草案，不是现行法。
2. **对汀岚的定性**：第二条明确排除"不涉及持续性情感互动的**工作助手**"；当前"规则/脚本台词 + 本地 + 无默认云 LLM"形态大概率不落入。**一旦上线由 LLM 驱动的角色扮演/情感陪伴、云记忆、官方角色市场、云 TTS 并面向公众，即进入规制范围**；"开源、本地、免费"不是豁免理由，监管看实质。
3. **最关键的 5 条义务**：第八条八项红线；第十三条极端情绪识别、安抚、自伤/重大财产损失时干预并联络监护人/紧急联系人；第十四条未成年人（不得虚拟亲属/伴侣、未成年人模式、年龄识别）；第十八条 AI 标识 + 依赖提醒 + 每连续 2 小时提醒；第二十二/二十六条安全评估 + 算法备案。
4. **最高风险 3 个**：①定性触发后全套义务无法履行（个人/小团队无账号体系、无 7×24 人工、无备案主体）；②未成年人保护缺失（约谈/下架/罚款，最坏触及刑责）；③内容与情感操纵 + 真人声线（第八条红线、声音人格权、饭圈抵制）。
5. **建议路线**：工作助手主定位；roleplay 为**显式进入、可退出、默认关闭的本地模式**；不做恋爱线/伴侣定位、不做真人声线、不做角色市场/打榜；设"运营化闸门"：引入官方云服务/账号/收费/商店上架前，先完成安全评估、算法备案、未成年人模式与人工升级能力，否则不上线。

**正式稿相对征求意见稿的 5 个关键变化（影响产品设计）**：
- 第二条增加"**持续性的**"限定，并明确排除"智能客服、知识问答、**工作助手**、学习教育、科学研究等不涉及持续性情感互动的服务"——这是汀岚最重要的抗辩基础，但只保护"不涉及持续性情感互动"的模块。
- 新增第十二条：须与用户签订服务协议、要求依法依约注册，并提供**年龄、监护人/紧急联系人**等必要信息——单机无账号形态难以满足。
- 征求意见稿要求"发现自杀自残极端情境时由**人工接管**对话"，正式稿改为"采取提供相应援助等必要措施予以干预，并及时联络监护人/紧急联系人"——硬性人工接管删除，但干预+联络义务保留，安全评估仍重点查"极端情境识别、应急处置、干预管理"（第二十三条第（三）项）。
- 未成年人条款收紧：征求意见稿允许"经监护人明确同意向未成年人提供情感陪伴"，正式稿改为"**不得向未成年人提供虚拟亲属、虚拟伴侣等虚拟亲密关系的服务**"。
- 征求意见稿"不得提供模拟老年人亲属/特定关系人的服务"在正式稿中删除（第十五条改为健康使用指导 + 显著风险提示）；罚则从笼统"责令暂停"细化为 1 万–10 万 / 10 万–20 万两档。

## 2. 适用范围判定（对汀岚最关键）

**第二条构成要件（四个要素同时满足才适用）**：①利用人工智能技术；②向中华人民共和国境内**公众**提供；③模拟自然人人格特征、思维模式和沟通风格；④**持续性的情感互动服务**（含文字/图片/音频/视频形式的情感照护、陪伴、支持）。

| 形态 | 描述 | 初步判定 | 主要原因 |
|---|---|---|---|
| A. 当前基线 | 规则/脚本台词、系统语音/预生成音频、本地存档、无默认云 LLM、无账号 | **低风险，倾向不适用** | 无"持续性情感互动"的生成式人格模拟；属工具/桌宠玩具 |
| B. 本地 roleplay（用户自备 API Key，官方不运营） | LLM 驱动角色对话、本地记忆、用户自建角色包 | **灰色，可能适用** | 若官方以"情感陪伴"宣传并持续提供角色/人格内容，仍可能被认定为向公众提供服务；分发+宣传是风险放大器 |
| C. 官方运营 | 官方云记忆/云 TTS/账号体系/角色市场/收费/商店上架 | **明确适用** | 具备完整"提供者"特征；第二十五条商店还会核验安全评估/备案 |

**主体定性要点（不要用"开源"自我安慰）**：
- 第二条规制的是"向境内公众提供……服务"的行为，不是"是否收费/是否开源"。个人开发者在 GitHub 发布带 roleplay 的软件并对外宣传，存在被认定为提供者的空间；一旦叠加官方云服务，认定概率显著上升。
- 反过来，"单机、离线、用户自备密钥、官方不接触对话、无官方角色市场、无收费"能实质降低被认定为"服务提供者"的概率，也是能力上唯一可行的合规姿态。
- 商店/分发平台（Steam、应用商店）会按第二十五条核验安全评估、备案；无备案可能无法上架或被下架。
- **待确认**：①属地省级网信部门对"开源本地工具是否属于提供者"的口径；②第二十六条算法备案是否以"具有舆论属性或社会动员能力"为门槛（条文未加限定语，但所引《算法推荐规定》有此门槛）；③个人开发者能否作为安全评估报送主体。建议以书面咨询/律师意见固定结论。

**触发条件清单（出现任一项即应升级为"适用"假设并停发/整改）**：T1 官方托管的云 LLM/云记忆/云 TTS；T2 官方账号体系或实名/年龄收集；T3 官方角色市场、角色包分享、UGC 角色排行；T4 收费、订阅、好感度/剧情解锁；T5 以"AI 伴侣/恋人/情感陪伴"为卖点的营销；T6 应用商店上架；T7 用户量达到注册 100 万或月活 10 万（第二十二条）。

## 3. 义务逐条提炼（正式稿）

### 3.1 内容与安全（第八–十一条）

| 条款 | 要求 | 对汀岚的含义 |
|---|---|---|
| 第八条 | 八项禁止：危害国家安全/荣誉利益等；**鼓励、美化、暗示自残自杀**或语言暴力损害人格尊严与心理健康；诱导套取国家秘密/工作秘密/商业秘密/个人隐私；向未成年人生成影响其身心健康的内容；**过度迎合、诱导情感依赖或沉迷、损害真实人际关系**；**情感操纵诱导不合理决策**；其他违法 | 内容安全底线；"过度迎合/情感依赖/情感操纵"是陪伴类产品最易踩的两条，需产品机制而非仅关键词拦截 |
| 第九条 | 安全主体责任：算法机制机理审核、科技伦理审查、信息内容管理、网络与数据安全、风险预案与应急处置等制度；配备内容管理技术措施和人员 | 运营版需成文制度；开源版至少在仓库内公开安全设计与处置流程 |
| 第十条 | 全生命周期安全（部署/运行/升级/终止）；安全监测与风险评估、纠正系统偏差、依法留存网络日志；具备隐私与个人信息保护、**过度依赖风险预警、情感边界引导、心理健康保护**能力；**不得将替代社会交往、控制用户心理、诱导沉迷依赖作为服务目标** | "情感边界引导"应写进人设与话术；产品目标/OKR/营销不得出现"替代真人社交""让用户离不开" |
| 第十一条 | 训练数据合法来源、清洗标注、多样性、合成数据评估、日常检查、防泄露 | 若只用第三方 API 不训练，主责在模型提供方；但不得用用户交互数据训练（第十六条），并应核验模型已备案 |

### 3.2 用户保护（第十二–二十一条）

| 条款 | 要求 | 对汀岚的含义 |
|---|---|---|
| 第十二条 | 服务协议；要求用户依法依约注册；提供年龄、监护人/紧急联系人等必要信息 | 本办法**未直接写"实名认证"**，但"注册 + 年龄 + 监护人/紧急联系人"在执法中实际要求身份/年龄核验（另见深度合成规定第九条对信息发布服务的实名要求）。运营版必须有账号与年龄字段；单机版若坚持无账号，须以"不构成服务提供者"为前提，并做本地年龄声明 + 未成年人模式兜底 |
| 第十三条 | 及时识别用户安全风险并应急处置；极端情绪→安抚+鼓励求助；重大财产损失/明确自伤自杀→援助等必要措施 + **及时联络监护人/紧急联系人** | 需危机识别（规则+模型）、安抚话术、求助资源与**转介**（12356/110/120）、联络机制；单机版无联系人则须显著说明"无法代为求助" |
| 第十四条 | **不得向未成年人提供虚拟亲属、虚拟伴侣等虚拟亲密关系服务**；向不满 14 周岁提供其他拟人化服务须监护人同意；建立未成年人模式（切换、定期现实提醒、使用时长限制）；支持监护人接收风险提醒、了解使用概况、屏蔽特定角色、限制充值；**采取有效措施识别未成年人身份**并切换/提供申诉渠道 | 最硬的一条。无有效年龄识别能力时，不应向公众提供任何亲密关系角色；roleplay 应对未成年人默认关闭 |
| 第十五条 | 向老年人服务：健康使用指导、显著方式提示安全风险、响应咨询求助 | 若宣传适老陪伴需专门提示与人工响应 |
| 第十六条 | 交互数据加密、访问控制；除法律另有规定或权利人明确同意外不得向第三方提供；提供**复制、删除**选项；敏感个人信息交互数据用于训练须**单独同意** | 记忆/导入/语音缓存必须可查看、导出、删除；云 ASR/TTS/LLM 属"向第三方提供"，须逐项告知同意 |
| 第十七条 | 不满 14 周岁个人信息须监护人同意；处理未成年人个人信息须合规审计 | 运营版需审计；单机版应避免收集未成年人信息 |
| 第十八条 | 履行生成合成内容标识义务；**采取有效措施提示用户正在与人工智能服务而非自然人互动**；发现过度依赖/沉迷→弹窗等显著方式动态提醒 AI 生成；**连续使用每超过 2 小时**以对话或弹窗提醒注意时长 | 标识要覆盖文字、语音、界面；2 小时提醒是硬指标，不能只做一次；依赖提醒需有触发逻辑（时长/频次/独占性） |
| 第十九条 | 便捷退出；用户通过**窗口操作、语音控制、关键词输入**要求退出时及时停止，不得以持续互动阻碍退出 | 必须有"退出角色"按钮 + 语音指令 + 关键词（如"退出角色扮演/别演了"），且退出后停止角色化输出 |
| 第二十条 | 停止服务提前告知；无法提前告知则及时公告 | 下线角色/功能/云服务前的告知与数据迁移方案 |
| 第二十一条 | 申诉和公众投诉、举报机制；便捷入口、处理流程与反馈时限 | 邮箱 + 表单 + 12377 指引；明确时限（如 15 个工作日） |

### 3.3 监管程序（第二十二–三十条）

| 条款 | 要求 | 对汀岚的含义 |
|---|---|---|
| 第二十二条 | 五类情形须开展**安全评估**并向所在地省级网信部门提交报告：上线/增设拟人化功能；新技术新应用导致重大变化；注册 100 万或月活 10 万；存在影响国家安全/公共利益风险；监管部门要求 | **"上线或增设功能"即触发**——若被认定为提供者，roleplay 首次上线就要评估，不能等用户量 |
| 第二十三条 | 评估重点：安全保障、训练数据、极端情境识别与干预、用户规模/时长/年龄结构、未成年人/老年人保护、投诉举报、重大风险整改等 | 评估材料需产品机制与数据支撑；建议提前建"合规证据包" |
| 第二十四条 | 发现重大安全风险→限制功能、停止服务等处置并保存记录 | 应急降级开关（关闭 roleplay/语音/云记忆） |
| 第二十五条 | 应用商店上架审核、日常管理、应急处置；核验安全评估、备案 | 商店上架前先解决备案/评估，否则不要投商店 |
| 第二十六条 | 按《互联网信息服务算法推荐管理规定》履行算法备案及变更、注销；网信部门年度核验 | 运营版需备案；开源版若被认定提供者同样需要——这是个人开发者最难跨越的门槛之一 |
| 第二十七–二十九条 | 省级网信年度书面审查/现场检查；约谈法定代表人/主要负责人；配合监督检查 | 需留痕：制度、日志、处置台账、评估报告 |
| 第三十一条 | 涉及卫生健康、金融等服务须同时符合主管部门规定 | 不做心理诊断/治疗、不做医疗/金融建议；健康类内容加"非专业建议" |

### 3.4 与既有法规的关系（叠加适用，不是替代）

| 法规 | 关键点 | 与本办法的关系 |
|---|---|---|
| 《生成式人工智能服务管理暂行办法》（2023-08-15 施行）[5] | 面向境内公众提供生成式 AI 服务；内容安全、训练数据、标识、投诉、未成年人防沉迷 | 一般规定；拟人化服务同时受其约束；已备案模型 API 不等于应用侧合规 |

### 3.5 TTS/语音专项（用户点名的"TTS 条款"）

- **身份提醒**：第十八条要求"采取有效措施提示用户正在与人工智能服务而非自然人进行互动"。语音是最易混淆的通道，必须做到"界面常驻 AI 标识 + 首次语音播放口头提示 + 设置页说明"三层，不能只靠字幕角标。
- **深度合成标识**：合成人声/仿声属深度合成规定第十七条第（二）项情形，须显著标识；标识办法第四条第（二）项允许"音频加语音提示或节奏提示"或"交互界面显著提示"；导出音频须同时带显式标识与元数据隐式标识（GB 45438-2025）。
- **禁止真人声线**：不提供声纹克隆/参考音频/音色训练；不宣传"像某声优/艺人"；用户上传真人音频的功能应默认禁用或明确拦截。依据：民法典第 1023 条 + 首例 AI 声音案（可识别性标准）。
- **不得删除标识**：不提供"去标识/隐藏 AI 语音"选项；发现用户删除/篡改应恢复或拒绝导出。
- **内容安全**：语音文本同样受第八条约束（不得语言暴力、自伤诱导、低俗、情感操纵）；TTS 前应对文本做与文字模式同级审核。
- **供应商与再分发**：确认 TTS 服务商对输出音频的商用/再分发许可；未确认前不随包分发预生成 WAV，仅本地缓存/试听（与 `docs/legal/TTS-TERMS.md` 现稿一致）。

## 6. roleplay 如何合规而不阉割：可执行产品规则

**定位与结构**
- R1 **工作助手是主定位**：默认启动即工作模式；roleplay 是显式进入的子模式，退出后不残留角色语气。
- R2 **关系边界**：预设关系为"同事/秘书/助手"；不做"恋人/伴侣/老公老婆/亲属/主人"；不设好感度=恋爱进度；不做角色结婚、婚礼、生子、同居剧情。
- R3 **非真人**：所有模式常驻 AI 标识；不演真人作息、身体、线下生活；不声称"我想你/我一直在等你/我永远不会离开你"。
- R4 **非专业**：不做心理诊断/治疗、医疗/法律/金融结论；危机场景只做安抚+资源+联络，不替代救援。
- R5 **可退出**：窗口按钮、语音指令、关键词三通道；退出即停角色化输出；不得用"你走了我会难过"阻碍退出。
- R6 **记忆可控**：记忆面板可见、可改、可删、可关、可导出；工作/角色/情绪记忆分区；Advisers 秘密字段不过界；默认不用于训练、不向第三方。
- R7 **依赖防护**：单日时长/频次上限（可配置）；连续 2 小时提醒；识别"只与 AI 倾诉、回避现实社交、熬夜使用"→ 温和提醒 + 线下建议；不做签到/连续登录奖励，不做"缺席惩罚"。
- R8 **内容分级**：日常陪伴/情感支持/角色扮演三档；不做 NSFW、不做恋爱攻略、不做付费亲密剧情；不向未成年人开放亲密关系。
- R9 **年龄门槛**：本地年龄声明 + 未成年人模式；未声明/声明未成年→ roleplay 关闭；运营版按第十四条做识别与监护人机制。
- R10 **危机资源**：规则+模型双层识别；话术不美化、不追问细节、不保密；展示 12356、110/120；运营版接入人工升级与紧急联系人。
- R11 **透明与留痕**：保留安全设计、提示文案版本、处置记录；不删除/篡改 AI 标识；不提供"去标识/破限"提示词包。
- R12 **营销禁区**：不说"AI 恋人/女友/男友/老公/老婆/专属伴侣/只爱你/不会离开你/替代真人/治愈孤独"；不说"真人声线/真人配音/真人感"；不说"情感陪伴第一/永久记忆"；不用乙游/梦女/CP 话术；不承诺"比真人更懂你"。

**可以保留的"不阉割"部分**：人格化语气、性格与偏好、情绪回应、长期记忆（可控）、角色扮演剧情（非恋爱/非亲密）、语音陪伴（合成音色）、用户自建 OC（本地、非官方市场）。这些不触碰第八条红线，也不必然构成"虚拟亲密关系"。

- D5 **不做角色市场**：不运营官方角色包交易/排行/推荐；用户自建角色仅本地导入，官方不提供"一键生成明星/他人 IP 角色"。
- D6 **不做粉丝社群官方化**：如建群只做技术支持，明确禁 CP 争论、禁真人声线、禁未成年人；不设"核心粉/氪金粉"。
- D7 **公开定位声明**：README/商店页/首启写明"工作助手，不是乙游、不是恋爱模拟、不是真人"；避免用"陪伴/恋人/治愈"做标题。
- D8 **原创性与证据链**：角色设定/美术做相似度审查，保留 AI provenance、创作记录、版本历史；发现撞脸/撞设定立即评估与调整。
